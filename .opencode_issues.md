# Phase issues (temporary, delete before finishing)

1. [diagnostics] `noise_limited` branch runs before `diverging`; when both
   train and val rise, a wide val stderr can mask an actual divergence.
2. [efficiency] Missing significance metadata (no `baseline_comparison.json`
   or missing row) is treated as "not False", so a candidate can be called
   viable without any significance evidence. Proxy cost measurements can also
   certify a tradeoff they did not measure.
3. [training] Checkpoints are written without verifying model weights are
   finite; a finite-grad optimizer overflow can persist a corrupted ckpt.
4. [training/resume] Curve history (`train_window`, val points, diagnoses) and
   validation-stream position are not checkpointed. On resume the curve
   restarts and validation passes read different slices than an uninterrupted
   run, so model selection / final val loss are not comparable.
5. [efficiency] The significance file's reference row is not checked against
   `--reference-name`; a candidate can be certified using significance against
   a different baseline than the one used for its loss/cost delta.
6. [efficiency] A latency cost measured in a single round (no per-round
   stderr) is still certified by the point estimate, so a one-sample timing can
   win the trade-off. Make "round count given but uncertainty missing" fail
   closed in the library; the benchmark already records `cost_ratio_n`.
7. [resume] Monitoring/optimization protocol flags (`val_every`, `val_batches`,
   `early_stop_patience`, `grad_accum`) are not restored from the checkpoint.
   A resume that omits them silently changes the validation cadence/selection
   protocol and the effective batch size, so checkpoint choice and final loss
   no longer describe the original run.
