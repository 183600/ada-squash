# Open issues found in this loop

## 1. `_seed_means` fabricates per-seed pairs for a multi-seed aggregate without `per_seed`

- File: `scripts/ablation.py` (`_seed_means`, `_paired_row_test`, `baseline_comparison`)
- Confirmed with synthetic input: a row shaped like a legacy aggregate
  (`seeds=[42,43,44]`, pooled `val_loss=2.0`, no `per_seed`) is treated as
  three independent seed observations all equal to 2.0. Pairing it against a
  reference with the same three seeds produces `p_one_sided=0.0` and
  `beats_reference_significantly=True`, with zero variance invented by the
  fallback.
- The normal summary writer (`aggregate_seed_summaries`) always writes
  `per_seed`, so current runs do not produce this shape. The function contract
  is still wrong: its docstring says the fallback is for a *single-run*
  summary, and a hand-written/older/external summary can turn a pooled mean
  into false significance instead of an unpaired row.
- Fix: only apply the no-`per_seed` fallback when the row names exactly one
  seed. A multi-seed row without per-seed losses has no pairing basis.
