# Experiment-design issues (temporary; delete before finishing)

1. [baseline / ablation] `baseline_comparison` certifies a variant against
   `ln_baseline` / `rmsnorm_baseline` at one fixed learning rate. `scripts/tune.py`
   can tune those arms, but `ablation.py` never consumes its
   `tuning_summary.json`, so a matrix can report a "significant" win over an
   untuned reference. Add an explicit tuning certificate and make the
   requirement fail-closed.
2. [baseline / calibration] `beats_tuned_simple_baseline` is a point-estimate
   threshold (`val_loss < tuned_ce`). The corpus, seeds and held-out batches
   are paired, so the claim should use a paired t-test over shared seeds and a
   Holm correction, and only certify when >= 3 seeds are shared.
3. [baseline / protocol] The simple-baseline calibration is attached without
   checking that the calibration seeds equal the matrix seeds; pairing a
   transformer seed with a count model fitted/evaluated on a different seed
   would fabricate a paired comparison.
4. [metrics] The metric helpers (`average_precision`, `roc_auc`, F1 averages,
   NDCG) have no independent self-check; a silent metric bug would invalidate
   every imbalance/ranking conclusion.
